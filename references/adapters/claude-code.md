# Claude Code Adapter

## Status

Supported. The RelayLoop core — the `RELAYLOOP_MESSAGE v1` envelope, the
`relay-loop/` workspace, the NDJSON audit logs, and all scripts — is plain
text and Python/Node, so it runs unchanged under Claude Code. This adapter
maps the only platform-specific layer: how role Agents are created and how
messages reach them.

## Install

Claude Code discovers skills from `~/.claude/skills/` (user-level) or
`.claude/skills/` (project-level):

```bash
tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT

git clone --depth 1 https://github.com/DylanZhangzzz/RelayLoop.git "$tmp"
mkdir -p ~/.claude/skills/relayloop
rsync -a "$tmp"/ ~/.claude/skills/relayloop/
```

Then start a fresh Claude Code session so the skill is discovered.

## Initialize

```bash
python3 ~/.claude/skills/relayloop/scripts/init_relay_loop.py \
  --project-name "ExampleProject" \
  --project-path /path/to/project \
  --adapter claude-code
```

In addition to the standard `relay-loop/` workspace, `--adapter claude-code`:

- generates `.claude/agents/relayloop-<role>.md` subagent definitions for every
  selected role except PM (PM is the main session);
- records `"adapter": "claude-code"` in `relay-loop/agents.json` and a
  `subagentPath` on each non-PM agent entry;
- filters Codex-app-only entries (for example `browser:control-in-app-browser`,
  `github:*`, `openai-docs`) out of the recommended skills lists.

Existing legacy `team-loop/` workspaces are detected and reused, same as the
Codex adapter.

## Concept Mapping

| Codex concept | Claude Code equivalent |
|---|---|
| PM Agent thread | The main Claude Code session |
| Role Agent threads (`codex_app.create_thread`) | `.claude/agents/relayloop-<role>.md` subagent definitions (generated by the initializer) |
| Thread titles / pinning (`codex_app.set_thread_title`, `set_thread_pinned`) | Not applicable in subagent mode; use session names in agent-teams or multi-session mode |
| Sending a thread message | Dispatching a subagent task whose prompt is the full `RELAYLOOP_MESSAGE v1` envelope |
| Codex worktrees | Claude Code worktree isolation for subagents / sessions |
| `codex_app.list_projects` | Not needed; the workspace lives in the current repo |
| Skill discovery `~/.codex/skills/` | `~/.claude/skills/` or project `.claude/skills/` |

Everything else — protocol envelope, workspace files, logging scripts,
approval boundaries, the Proof-Gated Loop — is identical across adapters.

## Operating Modes

### 1. Subagent mode (default, what the initializer generates)

The main session is the PM Agent. Dev, Test, Review, Version, Research, and UX
run as Claude Code subagents defined in `.claude/agents/relayloop-*.md`.

- PM dispatches by launching the matching subagent with the full
  `RELAYLOOP_MESSAGE v1` envelope as the prompt.
- Each subagent reads its role profile and the protocol from `relay-loop/`
  before acting, and replies using the Return Format fields.
- PM logs the dispatch and the response summary with
  `scripts/log_relayloop_event.py`, then updates `relay-loop/progress.md`.
- Subagents have no persistent thread ID; `threadId` in `agents.json` stays
  `null` and `subagentPath` identifies the role definition instead.
- Dev/Test subagents should run with worktree isolation when the repo has a
  valid `HEAD` (run `scripts/check_worktree_ready.py` first, same as Codex).

### 2. Agent-teams mode (experimental)

Claude Code agent teams give each teammate an independent context window and
direct messaging — the closest match to Codex role threads. The PM session
acts as the team lead; teammates load the same `relay-loop/agent-profiles/`
content. Treat this mode as experimental while the underlying Claude Code
feature is experimental; the workspace files and protocol are unchanged, so
switching modes later loses nothing.

### 3. Multi-session mode

Run each role as its own Claude Code session and coordinate purely through the
`relay-loop/` files: PM appends the envelope to `messages.ndjson`, role
sessions poll for messages addressed to their role and append responses. No
platform messaging is required at all — this mode demonstrates that the
protocol, state, and evidence layers are platform-independent.

## PM Startup Prompt

Open Claude Code in the target project and ask:

```text
Use the relayloop skill.

You are the PM Agent for this project.
Read relay-loop/protocol.md, relay-loop/agents.json, relay-loop/progress.md,
and relay-loop/agent-profiles/pm.md before acting.

Dispatch RELAYLOOP_MESSAGE v1 tasks to the relayloop-* subagents.
Wait for my project objective before dispatching work.
```

## Limitations

- Subagents report back to the PM session only; they do not message each other
  directly. PM routing (already RelayLoop's default) covers this.
- Agent-teams mode depends on an experimental Claude Code feature.
- Recommended-skills lists are advisory; availability depends on the skills
  actually installed in the local Claude Code environment.
